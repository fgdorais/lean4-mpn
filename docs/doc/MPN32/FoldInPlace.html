    In-place folds over a range of an array #

    lean4-scalar-arrays dropped the array folds foldInPlace and foldInPlaceThen in favor of the slice folds foldlInPlace and foldlInPlaceThen. This module defines the array folds again for UInt64Array, the wide accumulators of the 32-bit row kernels (Arch.Rows), as the same plain loops of sets as before, which the proofs are about, and @[csimp] lemmas make the compiler run the library's folds over the USize range [start, start + len) in their place (foldlInPlaceRange, foldlInPlaceRangeThen), which never convert the bounds to Nat. Nothing here is trusted: the in-place loop is the library's.

      Replaces each element of a from index start for len elements while threading an accumulator: for each k < len, the element x at start + k becomes the first component of f k hk x b, whose second component is the next accumulator. Returns the new array and the last accumulator. The compiler runs foldlInPlace on the slice of those elements instead (foldInPlace_eq_fast), which stores in place without checks.
